# Feature Specification: AgentOS CLI 入口与会话

**Feature Branch**: `003-agentos-cli`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "http://localhost:4321/projects/agent-os/cli/"

## 范围与边界

本功能为 AgentOS 提供面向终端使用者的命令行入口，让使用者可以准备工作区、选择 Agent、发送单条或连续消息，并在不同进程之间继续同一段会话。命令行只负责命令解析、输入输出、运行模式选择和退出结果表达；Agent 的模型调用、工具执行、会话协调与持久化由统一运行时处理。

本版本包含工作区初始化、帮助与版本查询、聊天命令、工作区与 Agent 选择、交互式输入、单条消息模式、会话复用、全新会话、退出码和错误输出。本版本不包含 Profile 增删改、Provider 管理、工具管理、会话列表、HTTP 服务、网关和定时触发命令；这些能力可在后续规格中独立定义。

## Clarifications

### Session 2026-11-17

- Q: CLI 应该如何确定每次聊天所使用的“使用者标识”？ → A: 使用当前操作系统账号作为使用者标识，v1 不提供命令行覆盖选项。
- Q: CLI 的退出码是否应固定为 0 表示成功、1 表示运行时启动失败、2 表示用法或配置错误、3 表示消息处理未成功？ → A: 固定为 0 成功、1 启动失败、2 用法或配置错误、3 处理未成功。
- Q: 交互式聊天中如果某一轮处理失败、但用户随后输入 `/exit` 或结束输入，进程最终应该返回哪种退出码？ → A: 交互正常结束返回 0；失败轮次即时报告，单条消息模式失败返回 3。
- Q: 初始化命令在未显式提供模型名称时，应该按什么顺序寻找默认模型配置？ → A: 只允许显式 `--model`；未提供即报错，不读取环境变量或 `.env`。
- Q: 初始化命令未指定 Provider 时，默认 Agent 应该使用哪个已配置的 Provider？ → A: 默认使用 `primary`；显式指定不存在的 Provider 直接报错，不静默切换。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 初始化可用的工作区 (Priority: P1)

使用者在尚未准备 Agent 文件的目录中执行初始化命令，显式提供要使用的模型名称后，系统创建最小可用的 AgentOS 工作区和默认 Agent，之后可以直接开始聊天；初始化不从环境变量或 `.env` 推断模型。

**Why this priority**: 没有可识别的工作区和默认 Agent，终端用户无法开始第一次对话；初始化必须先于聊天成立。

**Independent Test**: 在临时空目录执行初始化，检查默认目录、默认 Agent 和必要的引导文件；重复执行并检查已有内容保持不变，且全程不需要数据库、模型服务或网络。

**Acceptance Scenarios**:

1. **Given** 目标目录为空且提供了有效模型名称，**When** 使用者执行初始化，**Then** 系统创建工作区所需目录、默认 `main` Agent 和引导文件，并报告初始化成功；未指定 Provider 时默认记录 `primary`。
2. **Given** 工作区已有合法的 `main` Agent 和用户文件，**When** 使用者再次执行初始化，**Then** 系统保持已有内容不变，不覆盖用户配置。
3. **Given** 未显式提供模型名称且工作区不存在合法的默认 Agent，**When** 使用者执行初始化，**Then** 系统报告缺少必要配置并且不写入不完整的 Agent 文件。
4. **Given** 使用者指定自定义工作区，**When** 执行初始化，**Then** 所有新增内容只写入该目录，默认工作目录不被创建或读取。
5. **Given** 使用者显式指定不存在的 Provider，**When** 执行初始化，**Then** 系统报告配置错误，不生成引用未知 Provider 的默认 Agent。

---

### User Story 2 - 通过单条消息获得回答 (Priority: P1)

使用者选择工作区和 Agent，提交一条消息后得到回答并结束命令，适合脚本、快速验证和一次性任务。

**Why this priority**: 单条消息模式是最小可用的终端体验，也能让自动化脚本明确判断本次处理是否成功。

**Independent Test**: 使用本地模型替身提交一条纯文本消息，检查终端输出、处理结果和退出码；再用无效 Agent 或空消息验证命令不会启动处理链路。

**Acceptance Scenarios**:

1. **Given** 工作区、Agent、运行时配置和存储均可用，**When** 使用者执行单条消息命令，**Then** 系统提交消息、打印最终回答并以成功结果退出。
2. **Given** 使用者显式指定存在的 Agent，**When** 执行单条消息命令，**Then** 该 Agent 的配置和指令生效，不使用其他 Agent 的配置。
3. **Given** 使用者指定不存在或损坏的 Agent，**When** 执行命令，**Then** 系统在提交消息前报告可理解的用法错误，不静默切换到默认 Agent。
4. **Given** 消息为空或只包含空白字符，**When** 执行单条消息命令，**Then** 系统报告输入错误，不创建会话或轮次。

---

### User Story 3 - 进行可恢复的交互式对话 (Priority: P1)

使用者进入聊天命令后连续输入多条消息，使用 `/exit` 或输入结束信号离开；再次启动聊天时，系统继续同一身份和 Agent 的活跃会话，并保留之前的对话历史。

**Why this priority**: 多轮对话是终端使用 Agent 的主要方式；跨进程恢复保证使用者不会因退出命令或终端重启丢失上下文。

**Independent Test**: 在同一工作区、同一使用者和同一 Agent 下完成两轮消息，关闭并重新启动命令后发送第三轮，验证历史连续；再切换使用者或 Agent，验证历史隔离。

**Acceptance Scenarios**:

1. **Given** 使用者已进入交互式聊天，**When** 输入普通消息，**Then** 系统处理该消息并输出回答，随后继续等待下一条输入。
2. **Given** 使用者输入空行，**When** 聊天命令读取该输入，**Then** 系统提示消息不能为空，不创建轮次，并继续等待输入。
3. **Given** 使用者输入 `/exit` 或遇到输入结束，**When** 聊天命令结束，**Then** 系统关闭本次运行资源并正常退出。
4. **Given** 同一渠道、使用者和 Agent 已有活跃会话，**When** 使用者重新启动聊天并发送消息，**Then** 系统复用该会话并将历史提供给 Agent。
5. **Given** 使用者、渠道或 Agent 发生变化，**When** 发送消息，**Then** 系统使用隔离的会话，不读取其他身份的历史。

---

### User Story 4 - 安全地开始新会话 (Priority: P2)

使用者希望清空当前对话上下文但保留旧记录时，可以请求开始新会话。系统只归档空闲会话；如果旧会话仍在处理，则拒绝本次操作并保留原会话。

**Why this priority**: 新会话是长期使用中的必要控制，同时必须避免误删历史或打断正在执行的轮次。

**Independent Test**: 对已有空闲会话执行新会话选项，验证旧会话保留且新消息不带旧历史；对正在处理的会话并发执行，验证操作被拒绝且没有写入破坏性变更。

**Acceptance Scenarios**:

1. **Given** 当前 Agent 有一个空闲的活跃会话，**When** 使用者请求新会话并发送消息，**Then** 旧会话被归档，系统创建新的活跃会话，旧消息和审计记录保持可查询。
2. **Given** 当前 Agent 没有活跃会话，**When** 使用者请求新会话，**Then** 系统直接创建新的活跃会话并处理消息。
3. **Given** 当前会话有正在运行的轮次，**When** 使用者请求新会话，**Then** 系统拒绝归档并提示上一条消息仍在处理，正在运行的轮次不受影响。

### Edge Cases

- 工作区路径不存在、不可读或不可写时，系统报告路径错误并避免部分创建无法识别的 Agent 配置。
- 默认 Agent 文件存在但内容损坏时，初始化和聊天均报告配置错误，不把损坏文件当作缺失文件覆盖。
- Provider 名称目录不可读取或不包含显式 Provider 时，初始化在任何工作区写入前返回配置错误；不通过启动运行时或网络探测来补救。
- 运行时启动失败、模型调用失败、轮次超时或持久化未确认时，系统分别给出可理解的错误提示，并返回对应失败结果。
- 聊天过程中读取到输入结束时，系统将其视为正常结束，不重复提交最后一条消息。
- 交互模式中某一轮失败后，使用者仍可以继续输入；命令最终退出结果不冒充每一轮都成功。
- 使用者为自定义工作区启动聊天时，初始化、Agent 选择、引导文件和运行时读取必须使用同一工作区。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供统一的命令行入口，并至少支持初始化、聊天、帮助和版本查询。
- **FR-002**: 系统 MUST 在处理命令之前识别命令类型、选项和参数错误，并以稳定的退出结果通知调用方。
- **FR-003**: 初始化命令 MUST 创建工作区所需的最小目录结构、默认 `main` Agent 和必要的引导文件。
- **FR-004**: 初始化命令 MUST 是幂等的；已有合法文件 MUST 保持原样，重复初始化 MUST 不覆盖用户内容。
- **FR-005**: 初始化命令 MUST 要求显式提供有效的 `--model`；缺失或无效时 MUST 拒绝创建不完整的默认 Agent，并且不得读取环境变量或 `.env` 作为回退。
- **FR-006**: 系统 MUST 支持显式指定工作区，并在一次命令执行的所有阶段使用同一个规范化工作区。
- **FR-023**: 初始化命令未指定 Provider 时 MUST 为默认 Agent 使用 `primary`；显式指定的 Provider 名称 MUST 存在于本地非敏感 Provider 名称配置中，否则 MUST 在写入前报告配置错误，不得静默切换；名称校验不得启动 Spring、访问数据库或发起网络请求。
- **FR-024**: CLI MUST 支持全局 `--config <path>`；显式路径不存在、不可读或格式错误时 MUST 返回 2 且不得回退。未显式提供时 MUST 按契约规定的固定本地路径顺序查找；CLI 与 Boot MUST 使用同一配置文件格式和最终配置路径，CLI 仅读取 `agentos.providers` 名称键。
- **FR-007**: 聊天命令 MUST 支持显式选择 Agent；未显式选择时 MUST 按约定选择默认 `main`，且不得静默回退到另一个 Agent。
- **FR-008**: 聊天命令 MUST 支持单条消息模式；成功处理后 MUST 打印回答并结束进程。
- **FR-009**: 聊天命令 MUST 支持交互式多轮输入，并在每轮完成后继续等待下一条消息。
- **FR-010**: 交互式聊天 MUST 将 `/exit` 和输入结束视为正常结束，并释放本次命令使用的运行资源。
- **FR-011**: 空消息或空白消息 MUST 被拒绝，且不得创建会话、轮次或模型调用记录。
- **FR-012**: 命令行 MUST 将正常回答输出到正常输出流，将错误和诊断输出到错误输出流。
- **FR-013**: 系统 MUST 通过统一运行时提交消息；命令行 MUST NOT 自行实现模型调用、工具调用、会话租约或历史拼接。
- **FR-014**: 系统 MUST 按渠道、当前操作系统账号和 Agent 维度复用活跃会话，并保证不同维度之间的历史隔离；v1 MUST NOT 提供命令行选项覆盖使用者标识。
- **FR-015**: 会话、轮次、消息和调用记录 MUST 在处理完成后可被持久化，并在命令重启后恢复可用历史。
- **FR-016**: 聊天命令 MUST 支持请求新会话；该请求 MUST 只归档空闲活跃会话，不删除旧消息或审计记录。
- **FR-017**: 当新会话请求遇到正在运行的轮次时，系统 MUST 拒绝归档并保持原会话及其轮次不变。
- **FR-018**: 系统 MUST 使用固定退出码区分结果：0 表示成功，1 表示运行时启动失败，2 表示用法或配置错误，3 表示消息处理未成功。
- **FR-019**: 不依赖运行时的命令（帮助、版本和初始化）MUST 在数据库、Provider 或网络不可用时仍可执行。
- **FR-020**: 运行时依赖命令 MUST 在启动失败时尽早结束，不输出看似成功的模型回答。
- **FR-021**: Agent 选择无效、工作区不一致或配置损坏时，系统 MUST 在提交消息前报告原因并阻止处理。
- **FR-022**: 交互模式中的单轮失败 MUST 被明确报告，同时 MUST 保留继续输入的能力，除非运行时已经无法继续；只要运行时仍可继续且用户正常结束交互，进程最终 MUST 返回 0。单条消息模式的处理失败 MUST 返回 3。

### Key Entities

- **工作区**：保存 Agent 配置、引导内容、技能目录、记忆目录、输出目录和日志目录的用户工作目录。
- **Provider 配置**：一个可被 Agent Profile 引用的模型连接名称；初始化默认使用 `primary`。
- **Agent Profile**：描述一个可选择 Agent 的名称、模型配置、行为指令和工具权限。
- **会话**：由渠道、使用者和 Agent 共同确定的可持续对话上下文，包含活跃或已归档状态。
- **轮次**：一次用户消息从提交到最终结果的处理单元，关联输入、回答及中间调用记录。
- **命令执行**：一次 CLI 进程从参数解析到退出的生命周期，包含模式、工作区、输入和退出结果。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在数据库、模型服务和网络均不可用时，帮助、版本和初始化命令仍有 100% 的可执行成功率，并且不产生运行时连接尝试。
- **SC-002**: 在固定验收环境中，预热后独立执行 20 次初始化，至少 19 次在 2 秒内完成；重复初始化的文件覆盖率为 0%；未指定 Provider 的 20 次成功初始化均记录 `primary`，未知 Provider 的 20 次初始化均以退出码 2 零写入失败。
- **SC-003**: 在运行时配置有效时，单条消息命令在一次执行中完成提交、回答输出和退出，成功用例的回答交付率达到 100%。
- **SC-004**: 100% 的空消息、无效 Agent 和损坏配置用例在提交模型调用前失败，并且不产生新的会话或轮次。
- **SC-005**: 同一渠道、当前操作系统账号和 Agent 连续执行 20 次关闭并重启后，20/20 次恢复正确历史；对至少 20 对更换账号或 Agent 的隔离用例，历史串线次数为 0，且命令行无法覆盖账号标识。
- **SC-006**: 对空闲会话执行 20 次新会话，20/20 次都能查到保留的旧历史和新的活跃会话；对忙会话执行 20 次新会话请求，20/20 次拒绝归档且不新增轮次、消息或审计。
- **SC-007**: 退出码分类与命令结果一致率达到 100%；脚本可以仅依据固定的 0/1/2/3 退出码区分成功、启动失败、用法或配置错误、处理未成功。
- **SC-008**: 在交互式验收中，输入 `/exit`、输入结束和空行的行为符合定义的结果，且空行不会产生额外轮次；可继续的失败轮次后正常退出仍返回 0。

## Assumptions

- 使用者拥有目标工作区的读写权限，并可在命令行中看到正常输出和错误输出。
- CLI 与 Boot 共用同一份 Provider 配置格式；配置文件可通过全局 `--config` 显式指定，未指定时按 CLI 契约中的固定本地路径顺序查找。
- 初始化时模型名称必须通过显式 `--model` 提供；初始化不读取环境变量或 `.env` 中的模型名，也不把任何凭据写入工作区。
- CLI 使用当前操作系统账号作为会话使用者标识；v1 不允许通过参数或环境变量伪造、覆盖该标识。
- Agent 的模型连接和持久化能力由 AgentOS 运行时配置提供；CLI 不新增凭据管理方式。
- `primary` 是运行时预先配置的默认 Provider；初始化阶段只记录 Provider 名称，不验证或复制连接凭据。
- 工作区默认位于执行目录下的 `.AgentOS`，自定义路径通过命令选项提供。
- `main` 是默认 Agent 名称；初始化只生成最小的默认 Agent，不自动赋予工具权限。
- 会话历史和审计数据的长期保存遵循运行时存储策略；本功能只规定 CLI 必须复用和呈现该能力。
- 移动端界面、图形化管理台、远程身份认证和多租户隔离不在本版本范围内。
