# Contract: `AgentOS chat` 输出

## 1. 交互模式（`AgentOS chat`）

全部写标准输出，不输出 ANSI 控制序列。示意（`›` 行是用户输入）：

```text
› 把今天的天气写进 output/weather.md
我先查询天气。
  ⚙ http_get  {"url":"https://api.example.com/weather?city=…"}
  ✓ http_get  成功 · 820ms · {"temp":21,…}
  ⚙ write_file  {"path":"output/weather.md","content":"…"}

╭─ 需要授权：写入文件
│ 文件 output/weather.md
│ 方式 新建，312 字节
╰─
  1. 允许本次
  2. 允许，本会话不再询问…
  3. 拒绝（也可以直接输入原因，告诉 Agent 该怎么做）
请选择 [1-3]：1
  ✓ write_file  成功 · 15ms · 已写入 output/weather.md
已写入 output/weather.md，今天晴，21℃。
  ── 完成 · 模型调用 3 次 · 工具 2 次 · 6.2s
›
```

规则：

| 事件 | 输出 |
| --- | --- |
| `message.delta` | 原样打印，不换行，立即 flush |
| `tool.started` | 先结束未换行的文字行；打印 `  ⚙ <工具名>  <参数摘要>` |
| `tool.finished` | 打印 `  <✓/✗> <工具名>  <状态> · <耗时> · <结果摘要>`；状态为中文（成功、失败、超时、已拒绝、已跳过、已中断、结果未确认），`possiblyExecuted` 且非成功时追加"（可能已执行）" |
| `approval.*` / `input.*` | 不打印；提示由输入 broker 负责（006 现有行为） |
| `run.completed` | 结束文字行；调用过工具时打印 `  ── 完成 · 模型调用 N 次 · 工具 M 次 · 耗时`；最终回答已流式显示过时不再打印 |
| `run.failed` | 结束文字行；有已显示的文字时先打印 `  （回答未完成）`；打印 `  ── 失败：<message>`；错误码只用于决定文案，不直接显示 |
| `run.cancelled` | 结束文字行；打印 `  ── 已取消<；该操作可能已生效>` |

- 参数摘要、结果摘要在 CLI 上去掉换行并限长 80 个字符，超出以 `…` 结尾；完整内容在审计表。
- 退出码、持久化未确认提示与现在一致。

## 2. 非交互模式（`AgentOS chat --message "…"`）

| 流 | 内容 |
| --- | --- |
| 标准输出 | 成功时只有最终回答一行（与 007 之前逐字节一致） |
| 标准错误 | 工具行、终态行（格式同上）；失败时的错误说明（与现在一致） |

不使用流式模型调用；不出现确认交互（无人值守，006 现有行为）。

## 3. Ctrl+C

| 时机 | 行为 |
| --- | --- |
| 有轮次在执行 | 打印 `  （正在取消…）`，取消当前轮次；终态打印后回到 `›` 提示 |
| 再次按下（取消进行中） | 忽略，不重复取消 |
| 等待确认时按下 | 取消当前轮次；下一行输入会被丢弃并提示重新输入（已知限制，见 quickstart §6） |
| 没有轮次在执行 | 与现在一致：退出 chat |
| `--message` 模式 | 与现在一致：退出进程 |
