# Feature Specification: AgentOS 工具注册与安全执行

**Feature Branch**: `004-agentos-tool-system`

**Created**: 2026-11-18

**Status**: Draft

**Input**: User description: "http://localhost:4321/projects/agent-os/tool/"

## 范围与边界

本功能为 AgentOS 提供受控的工具能力：Agent 可以声明自己允许使用的工具，模型只能看到该最小集合，工具调用必须经过统一执行链、沙箱校验、审计和运行预算后才产生外部动作。首期交付内置 HTTP GET 工具及可供内部扩展复用的统一工具注册契约。

本功能不包含复杂的工具策略管理、工具搜索与渐进式暴露、容器级隔离、同一模型响应中的并行工具执行、远程工具协议的完整客户端能力，也不把 AgentOS 自身暴露为远程工具服务。这些能力需要独立规格和故障模型。

## Clarifications

### Session 2026-11-18

- Q: 当 Agent 没有单独配置时，工具循环应采用哪组默认安全上限？ → A: 模型最多 10 次、单工具最多 10 次、本轮工具最多 30 次、整轮 30 秒、最多 3 次重定向、响应正文最多 1 MiB。
- Q: HTTP 响应正文超过 1 MiB 上限时，系统应向模型和用户返回什么？ → A: 只返回不含正文的安全超限错误，不返回任何响应正文。
- Q: Agent 请求未授权或不存在的工具时，系统应让模型看到安全错误并继续本轮，还是立即结束本轮？ → A: 回传安全工具错误，允许本轮继续但不执行该工具；只有审计失败、租约丢失或整轮超时才终止本轮。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 为 Agent 配置最小工具集合 (Priority: P1)

Agent 作者在配置中声明需要的工具名称。系统在加载 Agent 时校验这些名称，并只向模型提供声明且已注册的工具；未注册、重复或不完整的工具定义在真正调用模型前就被发现。

**Why this priority**: 工具授权边界是所有外部动作的前提。没有精确的工具集合，模型可能看到不应使用的能力，错误也会在执行阶段才暴露。

**Independent Test**: 注册一个包含内置工具和扩展工具的目录，分别加载合法、未知、重复和缺少定义的配置，检查模型可见集合、失败时机和零外呼结果。

**Acceptance Scenarios**:

1. **Given** 目录中有多个已注册工具且 Agent 声明其中两个，**When** Agent 被加载，**Then** 模型只收到这两个工具的名称、描述和输入约束。
2. **Given** Agent 声明了目录中不存在的工具，**When** Agent 被加载，**Then** 系统指出配置文件和工具名称，且不发起模型请求、不创建新的工具执行记录。
3. **Given** 两个注册项使用相同名称或工具缺少名称、描述、输入约束，**When** 系统建立目录，**Then** 目录建立失败并报告配置错误。
4. **Given** 请求中出现 Agent 未授权或目录中不存在的工具名称，**When** 系统尝试解析调用，**Then** 系统把安全拒绝作为工具错误回传给模型，允许本轮继续，但不解析或执行同名的未授权组件。

---

### User Story 2 - 在副作用前完成安全治理和审计 (Priority: P1)

模型提出工具调用后，AgentOS 通过唯一的执行入口完成参数校验、租约和本轮预算检查，在真实动作前记录待执行审计；动作完成后更新同一条记录，并把可安全展示的结果交回下一轮上下文。

**Why this priority**: 文件、网络和业务系统调用都可能产生副作用。先授权、先记账、再执行，才能在失败、接管和恢复时知道发生了什么。

**Independent Test**: 使用一个可观察的替身工具覆盖正常返回、参数错误、沙箱拒绝、审计写入失败、执行超时和完成写入失败，核对执行次数、审计状态和模型收到的结果。

**Acceptance Scenarios**:

1. **Given** 工具调用通过授权、租约和预算检查，**When** 系统开始执行，**Then** 一条待执行记录已确认写入，之后才允许底层工具产生外部动作。
2. **Given** 待执行记录无法确认写入，**When** 模型请求工具，**Then** 底层工具执行次数为零，并返回可理解的审计失败信息。
3. **Given** 工具成功或失败，**When** 执行结束，**Then** 原待执行记录被更新为成功、失败、超时或沙箱拒绝之一，并把脱敏结果按调用标识回填到下一轮。
4. **Given** 工具已执行但完成记录无法确认，**When** 系统向用户报告结果，**Then** 系统明确提示操作可能已经发生，且不得自动重新执行同一个工具。
5. **Given** 过程事件通知发生异常，**When** 系统结束本轮，**Then** 后续过程通知停止，最终结果只交付一次，且通知异常不覆盖已确认的业务结果。

### User Story 3 - 安全调用受白名单保护的 HTTP 工具 (Priority: P1)

Agent 使用 HTTP GET 工具读取已授权地址。系统在每次请求前检查协议、域名和 URL 结构，限制重定向、响应大小和整轮截止时间，并在被拒绝或服务异常时返回不泄露凭证和正文的安全错误。

**Why this priority**: HTTP 是最直接的外部系统接入方式，也最容易把模型生成的地址变成越权访问或资源消耗。

**Independent Test**: 使用本地 HTTP 替身覆盖白名单域名、非白名单域名、根域与子域、非 HTTP 协议、带用户信息、连续重定向、超大响应、慢速响应和非 2xx 响应，检查实际请求数、结果和错误内容。

**Acceptance Scenarios**:

1. **Given** 目标是白名单中的绝对 HTTP/HTTPS 地址，**When** Agent 调用 HTTP GET，**Then** 请求被发送并返回受长度限制的正文。
2. **Given** 目标域名不在白名单、协议不受支持或 URL 含用户信息，**When** Agent 调用 HTTP GET，**Then** 请求在网络动作前被拒绝，替身服务收到零请求。
3. **Given** 响应要求跳转，**When** 系统跟随跳转，**Then** 每一跳重新检查白名单，超过配置上限、缺少有效地址或地址无效时安全失败。
4. **Given** 响应正文超过大小上限或持续传输直到截止时间，**When** 系统读取正文，**Then** 读取被取消；超限时只返回不含正文的安全超限错误，超时时只返回安全超时错误，持续分片不能延长整轮截止时间。
5. **Given** 服务返回非 2xx 状态，**When** 工具完成，**Then** 结果只包含状态和安全说明，不回显可能包含凭证的响应正文。

---

### User Story 4 - 在有界预算内完成连续工具调用 (Priority: P2)

Agent 在 ReAct 过程中可以连续调用工具，但模型调用次数、单工具调用次数、总工具调用次数和整轮时间均有明确上限。达到上限后系统返回安全结果并结束或收口本轮，不再发起隐含的补偿调用。

**Why this priority**: 外部工具可能变慢或反复失败；硬上限保证资源消耗和用户等待时间可预测。

**Independent Test**: 让模型替身持续产生工具调用，分别覆盖默认值、配置覆盖、单工具超限、总次数超限和截止时间耗尽，检查实际模型次数、工具执行次数、跳过记录和总耗时。

**Acceptance Scenarios**:

1. **Given** 模型持续请求工具直到达到模型调用上限，**When** 循环继续，**Then** 系统不发起下一次模型调用，并返回含上限原因的安全说明。
2. **Given** 单个工具或本轮所有工具达到各自上限，**When** 后续调用到达执行入口，**Then** 调用不进入底层工具，并产生对应的跳过审计记录。
3. **Given** 剩余截止时间不足以完成下一步模型、工具或审计操作，**When** 系统检查预算，**Then** 系统停止外呼并在预算内完成可确认的收尾。
4. **Given** 工具返回结果后模型已经给出最终答案，**When** 循环收口，**Then** 系统不把正常完成误判为达到上限，也不额外发起总结模型调用。

### Edge Cases

- Agent 配置为空工具集合时，模型请求不携带工具定义；模型随后伪造工具名称时必须得到安全拒绝。
- 工具输入 JSON 无法解析、缺少调用标识、调用标识重复或与历史不匹配时，整批调用安全失败，不生成假标识。
- 同一响应多次调用同名工具时，调用标识按模型给出的顺序关联，不能按参数或文本猜测。
- 沙箱、租约、截止时间或审计校验在执行前失效时，底层工具不得启动。
- 工具返回超长结果、包含凭证样式内容或异常链包含敏感 URL 时，交回模型和日志的内容必须脱敏并受长度限制。
- 工具完成后数据库连接、锁等待或提交结果不确定时，系统不能把不确定状态报告成已成功，也不能盲目重跑外部动作。
- 只有工具明确报告幂等、瞬时失败且副作用尚未开始时才允许一次自动重试；任何完成状态未知的情况都必须停止并进入未确认处理。
- 运行中的会话被其他使用者接管后，旧轮次的迟到工具结果不能覆盖新状态或继续写入。
- HTTP 重定向缺少 Location、Location 无法解析或命中 IP/子域边界时，系统安全失败。
- HTTP 服务在响应头后持续发送慢速正文时，正文读取仍受同一整轮截止时间约束；正文超限时不得回传已读取的正文片段。
- 未授权工具、参数错误和网络失败的用户提示可以区分原因，但不得包含完整 prompt、工具参数、响应正文或凭证；未授权工具错误可回传模型继续本轮。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供统一的工具目录，所有可用工具都必须具备唯一名称、描述和可验证的输入约束。
- **FR-002**: Agent MUST 能声明允许使用的工具名称；系统 MUST 按声明生成精确子集，未声明的工具不得提供给模型。
- **FR-003**: 系统 MUST 在 Agent 加载或请求开始前拒绝未知工具、重复工具名称和缺少必要定义的工具，并指出配置来源和具体名称；该加载期拒绝不得创建轮次、模型调用或工具执行记录。
- **FR-003a**: 运行中收到未授权或不存在的工具调用时，系统 MUST 通过安全工具错误回传给模型，允许本轮继续，但不得解析或执行同名的未授权组件。
- **FR-004**: 系统 MUST 将内置工具和内部扩展工具纳入同一工具调用契约；执行循环不得为不同来源复制独立分支。
- **FR-005**: 系统 MUST 通过唯一的统一执行入口调用工具；循环、命令行和其他入口不得直接调用底层工具实现。
- **FR-006**: 系统 MUST 在底层工具产生副作用前检查本轮上下文、会话租约、调用预算和沙箱授权。
- **FR-007**: 系统 MUST 在执行前确认一条待执行审计记录；该记录无法确认时 MUST 阻止真实工具执行。
- **FR-008**: 系统 MUST 在工具结束后更新原待执行记录，至少区分成功、失败、超时、沙箱拒绝、调用跳过和持久化未确认状态。
- **FR-009**: 系统 MUST 使用调用标识把工具结果回填到下一轮上下文，并保存该轮完整的工具请求和结果历史。
- **FR-010**: 系统 MUST 对普通业务错误、参数错误、未授权工具、沙箱拒绝和工具超时提供安全的可继续结果并允许模型继续本轮；审计失败、租约丢失和整轮截止时间耗尽 MUST 终止本轮。
- **FR-011**: 完成审计无法确认时，系统 MUST 明确说明操作可能已经执行，并 MUST NOT 自动重试底层工具；只有声明 `idempotent=true` 且明确报告 `executionStarted=false` 的工具，才允许对瞬时失败自动重试，默认最多 1 次重试（最多 2 次底层尝试），且重试必须消耗共享截止时间和调用预算。
- **FR-011a**: 完成状态未知、审计收尾未确认、租约丢失或无法判断底层动作是否已开始时，系统 MUST 禁止任何工具自动重试；非幂等工具始终不得自动重试。
- **FR-012**: 系统 MUST 对工具参数、工具结果、异常和日志进行脱敏与长度限制；普通工具结果默认最多 10000 个字符且可配置，截断后必须保留原始字符数和截断标记；不得输出完整 prompt、凭证、完整工具参数或可能含敏感信息的响应正文。
- **FR-013**: 系统 MUST 支持按配置限制模型调用次数、单工具调用次数和本轮工具总次数；未配置时默认分别为 10 次、10 次和 30 次；超过限制的调用不得进入底层工具，并 MUST 记录调用跳过状态。
- **FR-014**: 系统 MUST 使用一条贯穿模型调用、工具执行、网络正文读取和审计收尾的整轮截止时间；未配置时默认 30 秒；新响应分片不得延长该截止时间。
- **FR-015**: 截止时间耗尽、任务取消或会话租约失效后，系统 MUST 停止后续外呼、取消可取消的等待并清理执行资源。
- **FR-016**: 系统 MUST 提供 HTTP GET 工具，参数至少包含目标 URL；内部上下文参数不得成为模型可填写的工具参数。
- **FR-017**: HTTP 工具 MUST 只允许绝对 HTTP/HTTPS 地址，并 MUST 在默认空白的域名白名单中逐跳校验目标；域名比较不区分大小写，通配符只授权子域，IP 地址必须精确匹配。
- **FR-018**: HTTP 工具 MUST 拒绝 URL 中的用户信息、非白名单域名、非支持协议和超过配置上限的重定向；未配置时最多允许 3 次重定向；每次重定向都必须重新执行白名单校验。
- **FR-019**: HTTP 工具 MUST 限制响应正文大小；未配置时上限为 1 MiB；超过上限时取消读取，并只返回不含响应正文的安全超限错误。
- **FR-020**: HTTP 工具 MUST 对连接、响应头、正文读取和重定向共享剩余整轮预算；不得依靠持续分片或超出重试上限的自动重试延长用户等待时间，取消、截止或完成状态未知时不得重试请求。
- **FR-021**: HTTP 非 2xx、网络异常、无效重定向和响应超限 MUST 返回不包含响应正文、凭证或原始敏感异常链的安全结果。
- **FR-022**: 系统 MUST 支持同步和流式模型响应中的工具闭环，过程事件由循环驱动，终结通知最多交付一次；过程通知失败后不得继续回调。
- **FR-023**: 系统 MUST 保持工具调用定义中的返回直达等元数据，并在工具完成后按统一规则决定是否继续下一轮。
- **FR-024**: 工具注册和执行测试 MUST 覆盖合法工具、未知工具、重名、空集合、沙箱拒绝、先记后做、限次、超时、结果超限和恢复场景。
- **FR-025**: 真实外部服务联调 MUST 使用显式开启的独立验收路径；普通构建和默认测试不得发送真实凭证或网络请求。

### Key Entities

- **工具定义**：可被模型发现的工具能力，包含唯一名称、用途说明、输入约束和是否可直接返回。
- **Agent 工具授权**：某个 Agent 声明的允许工具名称集合，决定模型可见范围。
- **工具调用**：模型在某一轮中提出的一次带调用标识和输入的动作请求。
- **工具调用审计**：记录调用标识、工具名称、脱敏输入摘要、执行状态、结果摘要、耗时和持久化确认状态的记录。
- **沙箱策略**：对文件、命令和网络目标的允许范围与默认拒绝规则。
- **工具预算**：本轮共享截止时间、模型调用上限、单工具上限和总工具上限。
- **工具结果**：可回填模型上下文的脱敏文本及其截断、错误或状态标识。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 Agent 加载期授权验收中，100% 的未知、重复、未声明和缺少定义的工具配置在模型外呼前失败，且零新增轮次、模型调用和工具执行记录。
- **SC-002**: 在包含成功、失败、拒绝和超时的审计验收中，100% 的真实工具尝试都能关联到唯一调用标识和一条可查询的最终状态；执行前审计失败的用例真实执行次数为 0。
- **SC-003**: 在沙箱验收中，100% 的非白名单 HTTP、非法协议、用户信息 URL 和超限重定向用例产生零网络请求；白名单规则边界用例结果稳定一致。
- **SC-004**: 在限次验收中，模型和工具的实际调用次数均不超过配置上限，超限调用跳过记录与调用标识一一对应，且每个跳过调用的底层执行次数为 0。
- **SC-005**: 在截止时间验收中，慢模型、慢工具、慢正文、审计等待和持续流式响应 5 类场景各重复 20 次，共 100 次本地替身用例；每类 p95 均须在配置预算加 1 秒内返回，持续响应分片不能改变最终截止时间。
- **SC-006**: 在结果安全抽样中，100% 的用户提示、结构化日志和审计摘要不包含凭证、完整 prompt、完整工具参数或未受限的响应正文。
- **SC-007**: 在跨轮工具闭环验收中，100% 的成功工具结果按调用标识准确进入下一轮；正常最终回答不会触发额外的总结模型调用。
- **SC-008**: 新增一个遵守统一工具契约的内部工具时，不修改循环控制逻辑即可完成注册、Agent 授权和独立行为验收，且既有工具回归通过率达到 100%。
- **SC-009**: 在运行期授权边界验收中，100% 的未授权或不存在工具调用均返回安全工具错误，底层执行次数为 0，且模型能够继续本轮。

## Assumptions

- Agent 作者能够维护 Agent 配置并明确承担工具授权责任；默认工具集合为空，必须显式声明后才能使用工具。
- 工具目录在运行时启动或 Agent 加载时可用；工具名称、描述和输入约束属于非敏感配置。
- 沙箱默认拒绝所有未授权外部动作；HTTP 白名单由部署者按环境配置，工具不会因为 localhost、内网地址或 URL 外观而自动放行。
- 工具执行结果和审计记录遵循现有会话与存储策略；本功能规定可追溯状态和安全边界，不规定长期保留时长。
- 网络环境允许通过本地替身服务完成默认测试；真实天气或其他外部服务只在单独启用的验收路径中使用。
- 连接、数据库和外部服务均可能在截止时间内失败；系统优先保证边界、可追溯性和安全失败。
- 内部扩展工具可以复用统一工具契约；远程工具适配、复杂策略管理和并行执行留待后续规格。
