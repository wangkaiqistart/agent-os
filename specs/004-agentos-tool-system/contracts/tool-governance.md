# Contract: Tool Governance

## Purpose

定义每次模型工具调用的唯一执行协议。所有工具都必须通过该协议；任何入口不得直接调用底层工具实现。

## Inputs

- `ToolExecutor.execute(history, response, callbacks, context, budget, checkpoint)`
- 已授权且已套治理装饰器的 `ToolCallback` 列表
- 显式 `ToolContext`：轮次上下文、调用账本和共享预算
- 模型响应中的 ToolCall 列表

## Required sequence

1. 校验当前轮次、租约、截止时间和取消状态。
2. 校验同一响应的调用 ID：非空、批内唯一、可按名称建立 FIFO 队列。
3. 通过官方工具管理器执行，不在执行器中遍历 callback。
4. 每个治理回调领取对应调用 ID。
5. 在真实工具执行前写入并确认 `in_progress` 审计。
6. 解析输入 JSON、再次检查账本和预算，在虚拟线程/可取消等待中调用底层回调。
7. 将结果脱敏并按治理策略截断（普通工具默认最多 10000 个字符，截断标记计入上限）；更新原审计行。
8. 把完整对话历史中的助手工具请求和 ToolResponse 回填给循环。
9. 普通工具错误、参数错误、未授权工具、沙箱拒绝和工具自身超时可作为安全工具错误继续；审计失败、租约丢失和整轮超时终止本轮。
10. 若所有调用声明 `returnDirect`，可直接收口；否则由 ReActLoop 继续下一次模型调用。

## Limits and defaults

- 模型最大迭代：10。
- 每个工具最大调用：10。
- 本轮工具总数：30。
- 整轮业务截止时间：30 秒。
- 普通工具结果上限：默认 10000 个字符，可配置；`resultChars` 保存原始字符数，`resultTruncated` 标记截断。
- 重试策略：只有 `idempotent=true` 的工具可对由工具明确标记为“瞬时失败且确认未开始副作用”的结果自动重试，默认最多 1 次重试；每次尝试都消耗单工具和本轮工具预算，并共享同一 deadline。仅凭异常名称不能推断可重试；工具已经开始执行后的超时、连接中断或响应丢失均视为完成状态未知。
- 工具错误返回策略：安全错误响应；不得静默执行或重试底层副作用。完成状态未知、审计收尾未确认、租约丢失或非幂等工具一律禁止重试。
- 过程事件失败后停止后续过程通知；最终结果最多通知一次。

## Error semantics

| Condition | Result |
|----------|--------|
| 未授权/不存在工具 | 安全工具错误回模型，本轮可继续，零底层执行 |
| 参数 JSON 无效 | 安全工具错误回模型，本轮可继续 |
| 沙箱拒绝 | `sandbox_denied`，回模型，本轮可继续 |
| 工具自身超时 | 安全工具超时错误，回模型，本轮可继续 |
| 执行前审计未确认 | 终止本轮，底层执行次数为 0 |
| 执行后审计未确认 | 原审计行标记 `unconfirmed`，终止本轮，提示操作可能已发生，禁止重跑 |
| 租约丢失/整轮超时 | 终止本轮，取消后续外呼和可取消等待 |
| 正常最终回答 | 成功收口，不额外发送总结模型调用 |

## Forbidden paths

- 直接调用底层 `ToolCallback`。
- 使用 `ToolCallingAdvisor` 自动执行。
- 使用 `ThreadLocal` 传递轮次身份。
- 在 `ToolExecutor` 中自行构造 `ToolCallingManager`。
- 把工具参数、完整 prompt、凭证或完整响应正文写进日志、审计或用户错误。
